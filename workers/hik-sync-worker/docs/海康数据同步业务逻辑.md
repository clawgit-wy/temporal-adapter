# 海康数据同步业务逻辑文档

> 本文档描述 `hik-sync-worker` 服务的核心业务逻辑、架构设计、数据流及关键实现细节。

---

## 一、服务概述

| 项目 | 说明 |
|------|------|
| 项目名称 | `hik-sync-worker`（海康数据同步 Worker） |
| 服务用途 | 从安保系统 MySQL 数据库增量同步人员/人脸数据到海康中间库 PostgreSQL |
| 端口 | 18092 |
| 技术栈 | Spring Boot + Temporal SDK + 多数据源(MySQL+PostgreSQL) + Druid 连接池 + OkHttp + Guava |

---

## 二、系统架构

### 2.1 整体架构

```
┌──────────────────────┐         ┌──────────────────────────┐
│  MySQL (safety 库)   │  增量   │  PostgreSQL (海康中间库) │
│  - 4 张业务表        │ ──────> │  - 2 张中间表             │
│  safety_black_message│         │  tb_middle_person         │
│  safety_employee_msg │         │  tb_middle_face           │
│  safety_enter_reg    │         │                           │
│  safety_visitor_hp   │         │                           │
└──────────────────────┘         └──────────────────────────┘
        @Primary                          目标数据源
```

### 2.2 数据源配置

- **MySQL 数据源(safety 库)**:主数据源(`@Primary`),包含 4 张业务表
- **PostgreSQL 数据源(海康中间库)**:目标数据源,包含 2 张中间表
- **多数据源配置**:通过 `HikDataSourceConfig` 实现双数据源

## 三、核心业务流程

### Step 1:时间窗口计算

```java
start = 当前时间 - timeWindowMinutes分钟 (默认123)
end   = 当前时间
```

### Step 2:从 MySQL 并行查询 4 类增量数据

| certType | `111` |
| sex | `0` |
| mobile | `phone_no` |
| faceUrl | 生活照或身份证照 |
| status | `delete_falg=1` 或 `state='2'` 时为 `-1`(禁用),否则 `0`(正常) |

### Step 3:数据过滤与清洗

#### 3.3.1 必填字段校验

`jobNo`、`certificateNo`、`faceUrl`、`name` 任一为空则跳过该记录。

#### 3.3.2 人脸 URL 处理

```text
if URL 以图片扩展名结尾(.jpg/.jpeg/.png/.gif/.bmp):
    直接使用原 URL
elif URL 以 http://mp.yutong.com/mpapi/user-center/file/showPhoto 开头:
    替换为 http://safetyimg.yutong.com/mpproxy
elif URL 以 http://sg.yutong.com/emp-center/showPhoto 开头:
    替换为 http://safetyimg.yutong.com/sgproxy
else:
    通过 OkHttp 下载图片并转为 Base64 (写入 faceData 字段)
    faceUrl 设为 null
```

#### 3.3.3 二次校验

如果 `faceUrl` 和 `faceData` 都为空,则跳过该记录。

### Step 4:去重

按 `certificateNo`(证件号)去重,保留第一条记录。

### Step 5:批量写入 PostgreSQL 海康中间库

```java
// 使用 Guava Lists.partition 按 900 条/批分批
Lists.partition(list, 900);

// 每批执行两个 UPSERT 操作:
//   1. batchPersonSave → 写入 public.tb_middle_person 表 (ON CONFLICT certificate_no DO UPDATE)
//   2. batchFaceSave   → 写入 public.tb_middle_face 表   (ON CONFLICT certificate_no DO UPDATE)
```

## 十一、异常处理

| 阶段 | 处理策略 |
|------|----------|
| 查询阶段 | Activity 重试：30s超时，3次重试，2s退避 |
| 图片下载 | `IOException` 仅记录日志，返回空数组 |
| 图片处理 | Activity 重试：120s超时，2次重试，5s退避 |
| 批量写入 | Activity 重试：60s超时，3次重试，5s退避 |
