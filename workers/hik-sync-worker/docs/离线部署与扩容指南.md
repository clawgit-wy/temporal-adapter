# 海康数据同步 Worker - 离线部署与弹性扩容指南

> **适用场景**：Jenkins 构建 → 离线服务器 Docker 部署 → Docker Compose 弹性扩容
> **项目**：hik-sync-worker
> **更新日期**：2026-08-17

---

## 一、整体流程概览

```
┌─────────────────┐     ┌─────────────────┐     ┌──────────────────────────────────┐
│   Jenkins 服务器  │     │   联网中转服务器   │     │         离线生产服务器            │
│  (构建 Jar 包)   │────>│ (导出基础镜像)   │────>│  (导入镜像 + 构建 + 启动容器)    │
└─────────────────┘     └─────────────────┘     └──────────────────────────────────┘
        │                       │                        │

                                                    4. docker compose build
                                                    5. docker compose up -d --scale
```

## 三、Step 1：Jenkins 构建 Jar 包

### 3.1 Jenkins Pipeline 配置

在 Jenkins 中新建 Pipeline 任务，配置如下：

```groovy
// Jenkinsfile 片段 - 构建阶段
pipeline {
    agent any
    
    stages {
        stage('Checkout') {
            steps {
                checkout scm
            }
        }
        
        stage('Build Jar') {
            steps {
                sh '''
                    cd workers/hik-sync-worker
                    mvn clean package -DskipTests -Pprod
                '''
            }
        }
        
        stage('Archive Artifact') {
            steps {
                archiveArtifacts artifacts: 'workers/hik-sync-worker/target/*.jar'
                archiveArtifacts artifacts: 'workers/hik-sync-worker/Dockerfile.offline'
                archiveArtifacts artifacts: 'workers/hik-sync-worker/docker-compose.yml'
            }
        }
    }
}
```

### 3.2 或手动命令构建

```bash
cd /path/to/AdapterService/workers/hik-sync-worker
mvn clean package -DskipTests -Pprod
# 产物位置：target/hik-sync-worker-1.0.0.jar
```

### 3.3 验证产物

```bash
# 检查 Jar 是否生成
ls -lh target/hik-sync-worker-1.0.0.jar

# 验证 Jar 可执行（在有 JRE 的环境）
java -jar target/hik-sync-worker-1.0.0.jar --spring.profiles.active=prod --help 2>&1 | head -20
```

## 四、Step 2：准备基础镜像（联网服务器）

### 4.1 拉取基础镜像

在任意有网络的服务器上执行：

```bash
# 拉取 JRE 8 基础镜像
docker pull eclipse-temurin:8-jre

# 验证镜像
docker images | grep eclipse-temurin
```

### 4.2 导出为 tar 文件

```bash
# 导出镜像（文件名可自定义）
docker save -o eclipse-temurin-8-jre.tar eclipse-temurin:8-jre

# 查看文件大小（约 180MB）
ls -lh eclipse-temurin-8-jre.tar
```

### 4.3 验证 tar 文件

```bash
# 查看镜像信息
docker load -i eclipse-temurin-8-jre.tar
docker inspect eclipse-temurin:8-jre | head -30
```

## 五、Step 3：离线服务器部署

### 5.1 上传文件

```bash
# 使用 scp 或其他方式将文件上传到离线服务器
scp -r hik-sync-worker/ user@offline-server:/opt/apps/

# 或者使用 rsync（推荐，支持断点续传）
rsync -avz --progress hik-sync-worker/ user@offline-server:/opt/apps/hik-sync-worker/
```

### 5.2 导入基础镜像

```bash
# 在离线服务器上执行
cd /opt/apps/hik-sync-worker

# 导入基础镜像
docker load -i base-images/eclipse-temurin-8-jre.tar

# 验证镜像已导入
docker images | grep eclipse-temurin

# 预期输出：
# eclipse-temurin   8-jre   <image_id>   ...   180MB
```

### 5.3 构建 Worker 镜像

```bash
# 在离线服务器上执行
cd /opt/apps/hik-sync-worker

# 使用简化版 Dockerfile 构建
docker build -f Dockerfile.offline -t hik-sync-worker:1.0.0 .

# 验证镜像
docker images | grep hik-sync-worker

# 预期输出：
# hik-sync-worker   1.0.0   <image_id>   ...   <size>MB
```

### 5.4 验证镜像内容

```bash
# 启动临时容器验证 Jar 是否正确
docker run --rm -it hik-sync-worker:1.0.0 sh -c "java -version && ls -la /app/"

# 验证启动（注意：会连接 Temporal，可能失败，但 Jar 加载正常即可）
docker run --rm -e WORKER_SCENARIOS=hikSync -e TEMPORAL_ADDRESS=127.0.0.1:7233 hik-sync-worker:1.0.0 2>&1 | head -30
```

## 六、Step 4：Docker Compose 启动与扩容

### 6.1 配置环境变量

编辑 `.env` 文件或直接修改 `docker-compose.yml` 中的默认值：

```bash
cd /opt/apps/hik-sync-worker

# 创建环境变量文件（可选，推荐）
cat > .env << 'EOF'
# Temporal Server 地址
TEMPORAL_ADDRESS=temporal:7233

# 数据库连接（根据实际环境修改）
MYSQL_URL=jdbc:mysql://mysql-server:33306/safety?useUnicode=true&characterEncoding=utf-8&allowMultiQueries=true&useSSL=false
MYSQL_USERNAME=BP_QUERY
MYSQL_PASSWORD=your_mysql_password

PG_URL=jdbc:postgresql://pg-server:5432/ctm02brss_ctm02brssdb
PG_USERNAME=hikface
PG_PASSWORD=your_pg_password

# Worker 配置
WORKER_SCENARIOS=hikSync
JAVA_OPTS=-Xms512m -Xmx1024m
EOF
```

### 6.2 启动单个实例

```bash
# 方式 1：启动单个实例
docker compose up -d

# 方式 2：指定环境变量启动
TEMPORAL_ADDRESS=10.0.0.100:7233 \
MYSQL_URL="jdbc:mysql://10.0.0.200:33306/safety?useUnicode=true&characterEncoding=utf-8&useSSL=false" \
MYSQL_USERNAME=BP_QUERY \
MYSQL_PASSWORD=password \
PG_URL="jdbc:postgresql://10.0.0.201:5432/ctm02brss_ctm02brssdb" \
PG_USERNAME=hikface \
PG_PASSWORD=password \
docker compose up -d
```

### 6.3 验证启动

```bash
# 查看容器状态
docker compose ps

# 查看日志
docker compose logs -f worker

# 验证 Worker 已连接 Temporal（日志中应出现）
# "海康同步Worker已注册, taskQueue: HIK_SYNC_TASK_QUEUE"
```

## 七、弹性扩容操作

### 7.1 扩容到 N 个实例

```bash
# 扩容到 3 个实例
docker compose up -d --scale worker=3

# 扩容到 5 个实例
docker compose up -d --scale worker=5
```

### 7.2 缩容

```bash
# 缩容到 2 个实例
docker compose up -d --scale worker=2

# 缩容到 1 个实例
docker compose up -d --scale worker=1
```

### 7.3 查看当前实例数

```bash
# 查看所有 worker 实例状态
docker compose ps

# 查看容器列表（更详细）
docker ps -a --filter "label=com.docker.compose.service=worker"
```

### 7.4 健康检查

```bash
# 查看所有实例健康状态
docker compose ps

# 查看单个实例日志
docker compose logs worker  # 查看所有 worker 日志
docker compose logs worker-1  # 查看特定实例日志

# 验证 Worker 连接数
# 在 Temporal Server 上查看 HIK_SYNC_TASK_QUEUE 的 poller 数量
# poller 数应与扩容后的实例数一致
```

### 7.5 常见扩容场景

| 场景 | 操作命令 | 说明 |
|------|---------|------|
| 初始部署 | `docker compose up -d` | 默认 1 个实例 |
| 业务高峰 | `docker compose up -d --scale worker=5` | 快速扩容到 5 个实例 |
| 定时同步前 | `docker compose up -d --scale worker=3` | 同步任务前扩容 |
| 业务低谷 | `docker compose up -d --scale worker=1` | 减少资源消耗 |
| 持续高负载 | `docker compose up -d --scale worker=8` | 最大化处理能力 |

## 八、运维管理命令

### 8.1 日常运维

```bash
# 查看服务状态
docker compose ps

# 实时查看日志
docker compose logs -f --tail=100 worker

# 重启单个服务
docker compose restart worker

# 停止所有服务
docker compose down

# 停止服务（保留数据卷）
docker compose stop

# 移除所有容器和网络
docker compose down -v
```

### 8.2 更新部署

```bash
# 上传新的 Jar 包后，重建镜像并重启
docker compose up -d --build --force-recreate

# 或者仅重建镜像
docker compose build --no-cache
docker compose up -d

# 滚动更新（零停机，逐步替换）
docker compose up -d --scale worker=2  # 先启动新实例
# 然后逐步移除旧实例
docker compose up -d --scale worker=1
```

### 8.3 日志管理

```bash
# 查看最近 30 分钟日志
docker compose logs --since 30m worker

# 将日志导出到文件
docker compose logs worker > worker-logs.txt

# 日志轮转（已在 docker-compose.yml 中配置 json-file 驱动）
# max-size: 100m, max-file: 3
```

## 九、故障排查

### 9.1 Worker 无法连接 Temporal

```bash
# 检查网络连通性
docker exec -it <container_id> ping temporal

# 检查 Temporal Server 是否可达
docker exec -it <container_id> curl -v telnet://temporal:7233

# 检查环境变量
docker exec -it <container_id> env | grep TEMPORAL
```

### 9.2 数据库连接失败

```bash
# 检查 MySQL 连通性
docker exec -it <container_id> mysql -h <mysql_host> -u <user> -p <password> -e "SELECT 1"

# 检查 PostgreSQL 连通性
docker exec -it <container_id> psql -h <pg_host> -U <user> -d <database> -c "SELECT 1"
```

### 9.3 内存不足

```bash
# 调整 JVM 参数
JAVA_OPTS="-Xms256m -Xmx512m" docker compose up -d

# 或修改 docker-compose.yml 中的 deploy.resources.limits
```

### 9.4 端口冲突

```bash
# 检查端口占用
netstat -tlnp | grep 18092

# 修改 docker-compose.yml 中的端口映射
ports:
  - "18093:18092"
```
