# 楼宇门禁权限下发工作流设计文档

## 1. 概述

本文档描述基于 Temporal 的楼宇门禁权限下发工作流设计，涵盖富士设备（富士API）和新开普设备（预留）的权限下发、改写、增量管理、批量下发等业务场景。工作流设计参照 safety-service-master 中的门禁下发流程。

## 2. 富士设备接口规范

富士设备 API 基础路径由配置项 `fuji.api.base-url` 控制，所有接口均为 HTTP POST，Content-Type 为 application/json。

### 接口1: 发行校验 (CheckTokenState)

- **路径**: `/Api/FaceHandSet/CheckTokenState`
- **用途**: 校验卡号/人脸是否已有发行信息
- **请求参数**:

| 字段 | 类型 | 说明 |
|------|------|------|
| TokenType | int | 0=卡, 1=人脸 |
| Token | String | TokenType=0 时传卡号, TokenType=1 时传 staffNo |

- **响应参数**:

| 字段 | 类型 | 说明 |
|------|------|------|
| code | int | 200=存在发行信息, 500=不存在 |
| msg | String | 提示信息 |
| serverTime | String | 服务器时间 |
| result | Object | 发行详细信息（存在时返回） |

### 接口2: 人脸发行 (FaceIssue)

- **路径**: `/Api/FaceHandSet/FaceIssue`
- **用途**: 向设备下发人脸权限
- **请求参数**:

| 字段 | 类型 | 说明 |
|------|------|------|
| OperType | int | 0=发行 |
| Staff | StaffInfo | 人员信息 |
| BeginTime | String | 生效日期，如 `2025-09-10` |
| EndTime | String | 失效日期，如 `2034-11-06` |
| AuthorizeDeviceNo | List\<Integer\> | 授权设备编号列表 |
| ProjectGids | List\<String\> | 项目GID列表 |
| StaffState | int | 0=不变, 1=新增, 2=修改 |
| FacePicture | String | 人脸图片（Base64） |

### 接口3: 人脸发行改写 (FaceModify)

- **路径**: `/Api/FaceHandSet/FaceModify`
- **用途**: 修改已发行的人脸权限
- **请求参数**: 同接口2，区别为 `OperType=1`（改写），`StaffState=2`（修改）

### 接口4: 卡发行 (DoorIssue)

- **路径**: `/Api/FaceHandSet/DoorIssue`
- **用途**: 向门禁设备下发卡权限
- **请求参数**:

| 字段 | 类型 | 说明 |
|------|------|------|
| useModel | int | 使用模式，如 1 |
| orginazitionId | String | 组织ID |
| staffNo | String | 人员编号 |
| tokenId | String | 卡号 |
| endDate | String | 失效日期 |
| tokenOper | int | 操作类型，如 1 |
| stcm | String | 子卡类型ID |
| tcm | String | 卡类型ID |
| serialNo | String | 序列号 |
| token | String | 卡号 |
| icStartTimeL1-L4 | String | 时段左边界1-4 |
| icStartTimeR1-R4 | String | 时段右边界1-4 |
| CarPass | String | 车辆通行密码 |
| beginDate | String | 生效日期 |
| staffName | String | 人员姓名 |
| tokenType | int | 令牌类型，如 1 |
| AuthDevice | List\<String\> | 授权设备列表 |

### 接口5: 人脸增量权限及删除 (FaceModifyBypowerType)

- **路径**: `/Api/FaceHandSet/FaceModifyBypowerType`
- **用途**: 增量管理设备权限（增加/删除指定设备）
- **请求参数**: 同接口2，增加以下字段：

| 字段 | 类型 | 说明 |
|------|------|------|
| powerType | int | 0=增加设备权限, 1=删除设备权限 |

- **说明**: 只对 `AuthorizeDeviceNo` 列表中的设备产生增量操作，不影响其他设备

## 3. 工作流设计

### 3.1 整体架构

```
                    ┌─────────────────────┐
                    │   Temporal Server    │
                    └──────────┬──────────┘
                               │
                    ┌──────────┴──────────┐
                    │   WorkerFactory      │
                    └──────────┬──────────┘
                               │
        ┌──────────┬───────────┼───────────┬──────────┐
        │          │           │           │          │
┌───────┴──┐ ┌─────┴────┐ ┌────┴────┐ ┌─────┴────┐
│PermissionIssue│ │Permission│ │Permission│ │BatchIssue│
│   Workflow    │ │ Modify   │ │Increment │ │ Workflow │
│               │ │ Workflow │ │ Workflow │ │          │
└───────┬───────┘ └────┬─────┘ └────┬─────┘ └────┬─────┘
        │              │           │              │
        └──────┬───────┴────┬──────┴──────┬───────┘
               │            │             │
        ┌──────┴────────────┴─────────────┴──────┐
        │              Activity 层                 │
        │  CheckToken / FaceIssue / FaceModify     │
        │  CardIssue / FaceIncrement / Webhook     │
        └──────┬────────────┬─────────────┬───────┘
               │            │             │
        ┌──────┴──────┐ ┌───┴──────┐ ┌────┴──────┐
        │FujiApiClient│ │Xinkaipu  │ │Webhook    │
        │  (5个接口)   │ │ApiClient │ │  (HTTP)   │
        └─────────────┘ └──────────┘ └───────────┘
```

### 3.2 权限下发工作流 (PermissionIssueWorkflow)

参照门禁下发流程，实现完整的权限下发链路。

**流程图**:

```
开始
  │
  ├─ Step 1: 发行校验 (CheckTokenActivity)
  │    └─ 校验人员是否已有发行信息
  │       ├─ code=200: 已有发行信息，继续
  │       └─ code=500: 无发行信息，继续首次发行
  │
  ├─ Step 2: 人脸发行 (FaceIssueActivity)
  │    └─ 向设备下发人脸权限
  │       OperType=0, StaffState=1
  │
  ├─ Step 3: 卡发行 (CardIssueActivity)
  │    └─ 向门禁设备下发卡权限
  │
  ├─ Step 4: Webhook 回调 (WebhookActivity)
  │    └─ 通知业务系统下发结果
  │
  └─ 返回 DevicePermissionResult
```

**配置**:

| 项目 | 值 |
|------|-----|
| TaskQueue | `PERMISSION_ISSUE_TASK_QUEUE` |
| 场景标识 | `permissionIssue` |
| 最大并发 | 15 |
| Activity | CheckTokenActivity, FaceIssueActivity, CardIssueActivity, WebhookActivity |

**重试策略**:

| Activity | StartToCloseTimeout | 最大重试次数 | 退避策略 |
|----------|---------------------|-------------|---------|
| CheckTokenActivity | 15s | 3 | 默认 |
| FaceIssueActivity | 30s | 3 | 初始2s, 2.0倍退避 |
| CardIssueActivity | 30s | 3 | 初始2s, 2.0倍退避 |
| WebhookActivity | 15s | 5 | 默认 |

### 3.3 权限改写工作流 (PermissionModifyWorkflow)

用于修改已发行的人员权限（如更换设备、调整有效期等）。

**流程图**:

```
开始
  │
  ├─ Step 1: 发行校验 (CheckTokenActivity)
  │    └─ 确认人员已有发行信息
  │
  ├─ Step 2: 人脸改写 (FaceModifyActivity)
  │    └─ 修改已发行的人脸权限
  │       OperType=1, StaffState=2
  │
  ├─ Step 3: Webhook 回调 (WebhookActivity)
  │
  └─ 返回 DevicePermissionResult
```

**配置**:

| 项目 | 值 |
|------|-----|
| TaskQueue | `PERMISSION_MODIFY_TASK_QUEUE` |
| 场景标识 | `permissionModify` |
| Activity | CheckTokenActivity, FaceModifyActivity, WebhookActivity |

### 3.4 增量权限工作流 (PermissionIncrementWorkflow)

用于增量管理设备权限，支持增加和删除两种操作。

**流程图**:

```
开始
  │
  ├─ 根据 operationType 判断 powerType
  │    ├─ INCREMENT_ADD: powerType=0 (增加设备权限)
  │    └─ INCREMENT_DELETE: powerType=1 (删除设备权限)
  │
  ├─ Step 1: 人脸增量权限 (FaceIncrementActivity)
  │    └─ 对 AuthorizeDeviceNo 列表中的设备进行增量操作
  │
  ├─ Step 2: Webhook 回调 (WebhookActivity)
  │
  └─ 返回 DevicePermissionResult
```

**配置**:

| 项目 | 值 |
|------|-----|
| TaskQueue | `PERMISSION_INCREMENT_TASK_QUEUE` |
| 场景标识 | `permissionIncrement` |
| Activity | FaceIncrementActivity, WebhookActivity |

**说明**: 增量操作只影响 `AuthorizeDeviceNo` 中指定的设备，不影响其他已有设备权限。

### 3.5 批量权限下发工作流 (BatchPermissionIssueWorkflow)

支持批量并发下发多个人员的设备权限，内置限流保护。

**流程图**:

```
开始
  │
  ├─ 并发处理每个人员 (Async.function)
  │    │
  │    ├─ Step 1: 发行校验 (CheckTokenActivity)
  │    ├─ Step 2: 人脸发行 (FaceIssueActivity)
  │    └─ Step 3: 卡发行 (CardIssueActivity)
  │
  ├─ 收集所有结果 (Promise.get)
  │
  ├─ Webhook 回调 (WebhookActivity)
  │
  └─ 返回 DevicePermissionResult (含每个人员的结果详情)
```

**配置**:

| 项目 | 值 |
|------|-----|
| TaskQueue | `BATCH_ISSUE_TASK_QUEUE` |
| 场景标识 | `batchIssue` |
| 最大并发 | 20 |
| QPS 限制 | 20/s |
| Activity | 全部 Activity |

**限流原理**: 通过 `WorkerOptions.setMaxWorkerActivitiesPerSecond(20.0)` 在 Worker 层控制，避免对富士 API 造成过大压力。

## 4. 数据模型

### 4.1 统一请求模型 (DevicePermissionRequest)

工作流层统一使用此模型接收请求：

| 字段 | 类型 | 说明 |
|------|------|------|
| batchId | String | 批次ID |
| deviceType | String | 设备类型: FUJI / XINKAIPU |
| operationType | String | 操作类型: ISSUE / MODIFY / INCREMENT_ADD / INCREMENT_DELETE |
| staffList | List\<StaffInfo\> | 人员列表 |
| authorizeDeviceNo | List\<Integer\> | 授权设备编号列表（人脸设备） |
| authDevice | List\<String\> | 授权设备列表（卡设备） |
| beginTime | String | 生效时间 |
| endTime | String | 失效时间 |
| facePicture | String | 人脸图片（Base64） |
| projectGids | List\<String\> | 项目GID列表 |

### 4.2 人员信息模型 (StaffInfo)

对应富士接口中的 Staff 对象：

| 字段 | 类型 | 说明 |
|------|------|------|
| StaffNo | String | 人员编号 |
| StaffName | String | 人员姓名 |
| Sex | int | 性别 |
| OrganizationId | String | 组织ID |
| Rid | String | 角色ID |
| 其他字段 | - | 详见 StaffInfo.java |

### 4.3 结果模型 (DevicePermissionResult)

| 字段 | 类型 | 说明 |
|------|------|------|
| batchId | String | 批次ID |
| total | int | 总人数 |
| successCount | int | 成功数 |
| failCount | int | 失败数 |
| details | List\<StaffResult\> | 每个人员的详细结果 |
| status | String | 状态: COMPLETED / PARTIAL_FAILED |

## 6. 新开普设备接入说明

新开普设备 API 客户端 `XinkaipuApiClient` 已预留，包含以下方法：

| 方法 | 用途 | 状态 |
|------|------|------|
| issuePermission() | 权限下发 | 预留 |
| modifyPermission() | 权限改写 | 预留 |
| deletePermission() | 权限删除 | 预留 |

**接入步骤**:

1. 根据新开普实际接口文档，在 `XinkaipuApiClient` 中实现 HTTP 调用逻辑
2. 创建对应的 Activity 接口和实现类
3. 在 `TemporalWorkerConfig` 中注册新开普相关的 Worker
4. 创建新开普专用的工作流，或扩展现有工作流支持多设备类型

## 7. 改造指引

### 7.1 新增设备类型支持

当需要接入新的设备厂商时：

1. 在 `client/` 下创建新的 API Client（如 `DahuaApiClient`）
2. 在 `activity/` 下创建对应的 Activity 接口和实现
3. 在 `application-*.yml` 中添加新设备的配置
4. 在 `TemporalWorkerConfig` 中注册新的 Worker 场景
5. 创建新设备类型的工作流，或在现有工作流中根据 `deviceType` 字段分发

### 7.2 调整工作流流程

如需调整工作流中的步骤（如增加审批环节）：

1. 在 `workflow/` 下修改对应的 Workflow 接口，添加 `@SignalMethod` 和 `@QueryMethod`（如需人工审批）
2. 在 `workflow/impl/` 下修改实现类，插入新的 Activity 调用
3. 如需新增 Activity，按"新增第三方接口"流程操作
4. 更新本文档中的流程图说明

### 7.3 调整限流参数

如需调整批量下发的 QPS 限制：

修改 `TemporalWorkerConfig.java` 中 `TASK_QUEUE_BATCH_ISSUE` 对应的 Worker 配置：

```java
Worker worker = factory.newWorker(TASK_QUEUE_BATCH_ISSUE,
        WorkerOptions.newBuilder()
                .setMaxConcurrentActivityExecutionSize(20)    // 最大并发数
                .setMaxWorkerActivitiesPerSecond(20.0)         // QPS 限制
                .build());
```
