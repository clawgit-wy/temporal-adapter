# 海康数据同步使用说明

> **项目**: building-access-worker
> **模块**: HikSyncWorkflow（海康数据同步工作流）
> **集成来源**: hk-sync-job-master → building-access-worker
> **更新日期**: 2026-08-14

---

## 1. 功能概述

海康数据同步工作流（HikSyncWorkflow）从原独立的 `hk-sync-job-master` 服务整合而来，负责将安保系统 MySQL 数据库中的人员/人脸增量数据同步到海康中间库 PostgreSQL，供海康人脸识别设备消费。

### 1.1 与原服务的对比

| 维度 | 原 hk-sync-job-master | 整合后 HikSyncWorkflow |
|------|----------------------|----------------------|
| 架构 | 独立 Spring Boot 服务 | Temporal Workflow + Activity |
| 触发方式 | REST API 调用 | Temporal Workflow 启动 + REST API 触发 |
| 数据查询 | 串行查询4类数据 | **并行查询4类数据**（Async.function） |
| 图片处理 | 串行下载+Base64 | Activity 内处理，支持 Temporal 重试 |
| 批量写入 | Guava Lists.partition 900/批 | 同样 900/批，但带重试 |
| 失败处理 | 仅日志记录，无重试 | **Activity 自动重试** + 人工 Signal 干预 |
| 进度跟踪 | 无 | **QueryMethod 实时查询进度** |
| 数据库访问 | MyBatis 双数据源 | Spring JdbcTemplate 双数据源 |
| 时间窗口 | 硬编码 123 分钟 | **可配置**（请求参数 timeWindowMinutes） |

### 1.2 工作流信息

| 属性 | 值 |
|------|-----|
| 工作流接口 | `com.hik.worker.workflow.HikSyncWorkflow` |
| 实现类 | `com.hik.worker.workflow.impl.HikSyncWorkflowImpl` |
| TaskQueue | `HIK_SYNC_TASK_QUEUE` |
| 场景标识 | `hikSync` |
| 最大并发 | 10 |
| Activity | `HikSyncActivity`（6个方法） |
| 进度查询 | `@QueryMethod getSyncProgress()` |

## 3. 同步业务流程

### 3.1 整体流程图

```
开始
  │
  ├─ Step 1: 计算时间窗口
  │    ├─ 增量模式: start = now - timeWindowMinutes, end = now
  │    └─ 自定义模式: 使用请求中的 customStartTime / customEndTime
  │
  ├─ Step 2: 并行查询4类增量数据 (Async.function)
  │    ├─ queryBlackMessageList()      → 黑名单数据
  │    ├─ queryEmployeeMessageList()   → 员工台账数据
  │    ├─ queryEnterRegisterList()     → 外来人员备案数据
  │    └─ queryVisitorHairpinList()    → 访客数据
  │
  ├─ Step 3: 合并所有数据
  │
  ├─ Step 4: 人脸图片处理 (processFaceImages)
  │    ├─ 必填字段校验 (jobNo, certificateNo, faceUrl, name)
  │    ├─ 图片URL处理:
  │    │    ├─ 照片扩展名 → 直接使用
  │    │    ├─ mp.yutong.com → 替换为 safetyimg.yutong.com/mpproxy
  │    │    ├─ sg.yutong.com → 替换为 safetyimg.yutong.com/sgproxy
  │    │    └─ 其他 → OkHttp下载 + Base64编码
  │    └─ 过滤无图片记录
  │
  ├─ Step 5: 按证件号去重
  │
  ├─ Step 6: 批量写入海康中间库 (batchSyncToHik)
  │    ├─ 按 batchSize (默认900) 分批
  │    └─ 每批执行:
  │         ├─ UPSERT tb_middle_person (ON CONFLICT certificate_no)
  │         └─ UPSERT tb_middle_face (ON CONFLICT certificate_no)
  │
  └─ 返回 HkSyncResult
```

### 3.2 数据来源说明

| 数据来源 | MySQL 表 | orgId | certType | 特殊条件 |
|----------|----------|-------|----------|----------|
| 黑名单 | safety_black_message | HDM00001 | 111 | delete_falg=1或state='2'时status=-1 |
| 员工台账 | safety_employee_message | ZZRY0001 | 131 | sex: 0→1(男), 1→2(女) |
| 外来人员备案 | safety_enter_register | BA000003 | 990 | 无 |
| 访客 | safety_visitor_hairpin | FK000002 | 990 | delete_falg=0 AND vendor_state IN (1,5,8,9,10,11) |

## 4. API 接口

### 4.1 启动同步工作流

通过 Temporal WorkflowClient 启动工作流：

```java
// 创建请求
HkSyncRequest request = HkSyncRequest.builder()
    .syncType("INCREMENTAL")      // 增量同步
    .timeWindowMinutes(123)       // 时间窗口123分钟
    .batchSize(900)               // 批量大小900
    .build();

// 启动工作流
HikSyncWorkflow workflow = workflowClient.newWorkflowStub(
    HikSyncWorkflow.class,
    WorkflowOptions.newBuilder()
        .setTaskQueue("HIK_SYNC_TASK_QUEUE")
        .setWorkflowId("hik-sync-" + System.currentTimeMillis())
        .build());

HkSyncResult result = workflow.syncToHik(request);
```

### 4.2 查询同步进度

```java
// 通过 WorkflowStub 查询进度
String progress = workflow.getSyncProgress();
// 返回格式: "已处理: 150/300, 成功: 148, 失败: 2, 状态: RUNNING"
```

### 4.3 请求参数说明

| 参数 | 类型 | 必填 | 默认值 | 说明 |
|------|------|------|--------|------|
| syncType | String | 是 | - | INCREMENTAL=增量同步, FULL=全量同步 |
| timeWindowMinutes | int | 否 | 123 | 增量同步的时间窗口(分钟) |
| customStartTime | String | 否 | - | 自定义开始时间 (yyyy-MM-dd HH:mm:ss) |
| customEndTime | String | 否 | - | 自定义结束时间 (yyyy-MM-dd HH:mm:ss) |
| batchSize | int | 否 | 900 | 批量写入大小 |
| parallelImageDownload | boolean | 否 | false | 是否并行下载图片 |
| maxParallelImages | int | 否 | 10 | 最大并行图片下载数 |

### 4.4 返回结果说明

| 字段 | 类型 | 说明 |
|------|------|------|
| syncType | String | 同步类型 |
| blackListCount | int | 黑名单数据数 |
| employeeCount | int | 员工台账数据数 |
| registerCount | int | 外来人员备案数据数 |
| visitorCount | int | 访客数据数 |
| totalAfterFilter | int | 过滤后总数据数 |
| totalAfterDedup | int | 去重后总数据数 |
| successCount | int | 成功写入数 |
| failCount | int | 失败数 |
| status | String | 状态: COMPLETED/PARTIAL_FAILED/FAILED |
| errorMessage | String | 错误信息 |

## 8. 定时调度配置

原 `hk-sync-job-master` 通过外部 HTTP 调用触发同步。整合后推荐通过 Temporal 定时工作流或外部 Cron 触发：

### 方式1: Temporal Cron Workflow（推荐）

```java
// 启动定时工作流，每2小时执行一次
HikSyncWorkflow cronWorkflow = workflowClient.newWorkflowStub(
    HikSyncWorkflow.class,
    WorkflowOptions.newBuilder()
        .setTaskQueue("HIK_SYNC_TASK_QUEUE")
        .setWorkflowId("hik-sync-cron")
        .setCronSchedule("0 */2 * * *")  // 每2小时
        .build());

// 首次启动（后续由 Temporal 自动调度）
WorkflowClient.start(cronWorkflow::syncToHik, request);
```

### 方式2: 外部 Cron + REST 触发

在业务系统中配置 Cron 任务，通过 Temporal WorkflowClient 启动同步工作流。

### 推荐调度频率

| 场景 | Cron 表达式 | 说明 |
|------|------------|------|
| 高频同步 | `0 */2 * * *` | 每2小时（时间窗口=123分钟，有重叠覆盖） |
| 标准同步 | `0 0,6,12,18 * * *` | 每6小时 |
| 低频同步 | `0 0 2 * * ?` | 每天凌晨2点（配合 FULL 模式） |

### 9.3 常见问题排查

| 问题 | 可能原因 | 排查方式 |
|------|----------|----------|
| 查询数据为空 | 时间窗口内无更新数据 | 检查 MySQL 中 update_time 是否在窗口内 |
| 图片下载失败 | 图片URL不可访问或网络超时 | 查看 Activity 重试日志，检查 URL 代理映射 |
| PostgreSQL写入失败 | 连接异常或字段约束冲突 | 检查 PG 连接配置，查看 ON CONFLICT 字段 |
| 工作流超时 | 数据量过大或图片处理慢 | 增大 Activity StartToCloseTimeout 或减小 batchSize |
| 访客数据未同步 | vendor_state 不在允许列表 | 确认 vendor_state IN (1,5,8,9,10,11) |
