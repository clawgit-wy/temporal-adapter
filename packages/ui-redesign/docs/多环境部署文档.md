## 3. 环境变量说明

项目根目录下的 `.env` 文件系统：

```
.env                  # 所有环境共享的基础配置
.env.development      # 开发环境差异化配置
.env.test             # 测试环境差异化配置
.env.production       # 生产环境差异化配置
.env.example          # 模板（参考用）
.env.local            # 本地覆盖（不提交，最高优先级）
.env.{mode}.local     # 特定 mode 本地覆盖（不提交）
```

**加载优先级**（从高到低）：
1. `.env.{mode}.local`
2. `.env.{mode}`
3. `.env`

## 5. 构建与部署步骤

### 5.1 各环境构建命令

```bash
# 开发环境构建
pnpm build:dev

# 测试环境构建
pnpm build:test

# 生产环境构建（默认）
pnpm build:prod
# 或简化命令
pnpm build
```

### 5.2 部署流程（生产环境示例）

```bash
# 1. 拉取最新代码
cd /Users/apple/Desktop/AdapterService/ui-redesign
git pull origin main

# 2. 安装依赖
pnpm install --frozen-lockfile

# 3. 构建生产包
pnpm build:prod

# 4. 备份当前版本（用于回滚）
sudo cp -r /var/www/ui-redesign /var/www/ui-redesign.bak.$(date +%Y%m%d%H%M%S)

# 5. 部署新版本
sudo rm -rf /var/www/ui-redesign/*
sudo cp -r dist/* /var/www/ui-redesign/

# 6. 修改运行时配置（指向生产环境后端）
sudo vi /var/www/ui-redesign/config.js
# 修改 appEnv: 'production'
# 修改 apiBaseUrl: '/api/v1'（如果不变可跳过）

# 7. 重载 Nginx
sudo nginx -t && sudo nginx -s reload

# 8. 验证部署
curl -I http://localhost/
curl -I http://localhost/api/v1/cluster-info
```

### 5.3 自动化部署脚本（示例）

创建 `deploy.sh`：

```bash
#!/bin/bash
set -e

ENV=${1:-production}
DEPLOY_DIR=/var/www/ui-redesign
BACKUP_DIR=/var/www/ui-redesign.bak.$(date +%Y%m%d%H%M%S)

echo "[1/6] 拉取最新代码..."
git pull origin main

echo "[2/6] 安装依赖..."
pnpm install --frozen-lockfile

echo "[3/6] 构建 $ENV 环境..."
case $ENV in
  dev)  pnpm build:dev ;;
  test) pnpm build:test ;;
  prod) pnpm build:prod ;;
  *)    echo "未知环境: $ENV"; exit 1 ;;
esac

echo "[4/6] 备份当前版本到 $BACKUP_DIR..."
sudo cp -r $DEPLOY_DIR $BACKUP_DIR

echo "[5/6] 部署新版本..."
sudo rm -rf $DEPLOY_DIR/*
sudo cp -r dist/* $DEPLOY_DIR/

echo "[6/6] 重载 Nginx..."
sudo nginx -t && sudo nginx -s reload

echo "部署完成！访问 http://$(hostname -I | awk '{print $1}')/"
```

使用方式：
```bash
chmod +x deploy.sh
./deploy.sh prod
```

## 6. Nginx 配置示例

### 6.1 生产环境配置

创建 `/etc/nginx/conf.d/ui-redesign.conf`：

```nginx
# Temporal UI Redesign - 生产环境配置
server {
    listen 80;
    server_name temporal-ui.example.com;

    # HTTP 强制跳转 HTTPS
    return 301 https://$host$request_uri;
}

server {
    listen 443 ssl http2;
    server_name temporal-ui.example.com;

    # SSL 证书
    ssl_certificate     /etc/nginx/ssl/fullchain.pem;
    ssl_certificate_key /etc/nginx/ssl/privkey.pem;
    ssl_protocols       TLSv1.2 TLSv1.3;
    ssl_ciphers         HIGH:!aNULL:!MD5;

    # 静态资源根目录
    root /var/www/ui-redesign;
    index index.html;

    # gzip 压缩
    gzip on;
    gzip_vary on;
    gzip_min_length 1024;
    gzip_types text/plain text/css application/json application/javascript text/xml application/xml application/xml+rss text/javascript image/svg+xml;

    # 静态资源缓存策略
    location /assets/ {
        expires 1y;
        add_header Cache-Control "public, immutable";
        try_files $uri =404;
    }

    # 运行时配置文件（不缓存，便于实时修改）
    location = /config.js {
        add_header Cache-Control "no-cache, no-store, must-revalidate";
        expires off;
    }

    # favicon
    location = /favicon.svg {
        expires 1d;
        access_log off;
    }

    # API 反向代理 → Temporal UI Server
    location /api/v1/ {
        proxy_pass http://127.0.0.1:8080;
        proxy_http_version 1.1;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;

        # CSRF Cookie 处理（剥离 Secure，HTTP 下也能工作）
        proxy_cookie_flags ~secure off;
        proxy_cookie_path / /;

        # WebSocket 支持（如使用 Temporal 的实时特性）
        proxy_set_header Upgrade $http_upgrade;
        proxy_set_header Connection "upgrade";

        # 超时设置
        proxy_connect_timeout 60s;
        proxy_send_timeout 60s;
        proxy_read_timeout 60s;
    }

    # SPA 路由：所有未匹配的路径回退到 index.html
    location / {
        try_files $uri $uri/ /index.html;
        add_header Cache-Control "no-cache, no-store, must-revalidate";
    }

    # 安全头
    add_header X-Frame-Options "SAMEORIGIN" always;
    add_header X-Content-Type-Options "nosniff" always;
    add_header X-XSS-Protection "1; mode=block" always;
    add_header Referrer-Policy "strict-origin-when-cross-origin" always;

    # 上传文件大小限制
    client_max_body_size 10m;

    # 访问日志
    access_log /var/log/nginx/ui-redesign.access.log;
    error_log  /var/log/nginx/ui-redesign.error.log;
}
```

## 7. 运行时配置切换

### 7.1 设计原理

项目支持**无需重新构建**即可切换环境配置。原理：

1. `index.html` 在主入口前加载 `/config.js`
2. `config.js` 设置 `window.__APP_CONFIG__` 对象
3. 应用启动时，`src/lib/config.ts` 优先读取 `window.__APP_CONFIG__`，覆盖构建期注入的值

```
优先级：window.__APP_CONFIG__ > import.meta.env > 默认值
```

### 7.2 部署后修改配置

部署完成后，如需切换环境，只需修改 `/var/www/ui-redesign/config.js`：

```bash
sudo vi /var/www/ui-redesign/config.js
```

修改内容示例（切换到测试环境配置）：

```javascript
window.__APP_CONFIG__ = {
  appEnv: 'test',
  appName: 'Temporal UI Redesign',
  appVersion: '0.1.0',
  namespace: 'default',
  defaultTheme: 'dark',
  apiBaseUrl: '/api/v1',
  basePath: '/',
  cdnBase: '',
  enableDevtools: true,
  enableSourcemap: false,
  logApiRequests: true,
  useMock: false,
};
```

修改后**无需重启 Nginx**，刷新浏览器即可生效（因为 `config.js` 配置了 `no-cache`）。

### 7.3 Nginx 动态注入配置（高级用法）

如果希望按请求来源动态返回不同配置，可使用 Nginx njs 模块：

```nginx
# /etc/nginx/conf.d/ui-redesign.conf

js_import /etc/nginx/conf.d/config.js;

location = /config.js {
    js_content config.generate;
}
```

`/etc/nginx/conf.d/config.js`：

```javascript
function generate(r) {
    const env = r.args.env || 'production';
    const config = {
        production: { appEnv: 'production', logApiRequests: false },
        test: { appEnv: 'test', logApiRequests: true },
        development: { appEnv: 'development', logApiRequests: true },
    };
    r.headersOut['Content-Type'] = 'application/javascript';
    r.return(200, `window.__APP_CONFIG__ = ${JSON.stringify(config[env] || config.production)};`);
}

export default { generate };
```

访问 `https://example.com/config.js?env=test` 即可动态返回测试环境配置。

```bash
#!/bin/bash

    ;;
  stop)
    echo "停止 Temporal UI Redesign..."
    sudo systemctl stop nginx
    cd /opt/AdapterService && docker compose down
    echo "停止完成"
    ;;
  restart)
    $0 stop
    sleep 2
    $0 start
    ;;
  status)
    echo "=== Nginx 状态 ==="
    sudo systemctl status nginx --no-pager -l | head -10
    echo ""
    echo "=== Docker 服务状态 ==="
    cd /opt/AdapterService && docker compose ps
    echo ""
    echo "=== 站点访问测试 ==="
    curl -sI http://localhost/ | head -5
    ;;
  *)
    echo "用法: $0 {start|stop|restart|status}"
    exit 1
    ;;
esac
```

## 9. 常见问题排查

### 9.1 页面空白，控制台报 404

**原因**：静态资源路径错误，通常是 `VITE_BASE_PATH` 与实际部署路径不匹配。

**解决**：
```bash
# 检查部署路径
ls /var/www/ui-redesign/

# 如果部署在子路径，修改 .env.production
echo 'VITE_BASE_PATH=/ui-redesign/' >> .env.production
pnpm build:prod

# 重新部署
sudo cp -r dist/* /var/www/ui-redesign/
sudo nginx -s reload
```

### 9.2 API 请求返回 502 Bad Gateway

**原因**：Temporal UI Server 未启动或不可达。

**解决**：
```bash
# 1. 检查 Temporal UI Server 是否运行
curl http://localhost:8080/api/v1/cluster-info

# 2. 检查 Docker 容器状态
docker compose ps

# 3. 查看日志
docker compose logs temporal-ui --tail 50

# 4. 检查 Nginx 配置中的 proxy_pass 地址
sudo nginx -T | grep proxy_pass
```

### 9.3 API 请求被 CSRF 拦截（403 Forbidden）

**原因**：Temporal UI Server 启用了 CSRF 保护，Cookie 的 Secure 标志在 HTTP 下无法存储。

**解决**：
- 开发环境：Vite proxy 已自动剥离 Secure 标志，无需处理
- 生产环境：使用 HTTPS，或在 Nginx 中添加 `proxy_cookie_flags ~secure off;`

### 9.4 创建工作流/计划任务失败

**原因**：Temporal Server 的 `disableWriteActions` 设置为 `true`。

**解决**：
```bash
# 检查 Temporal UI Server 配置
curl http://localhost:8080/api/v1/settings | jq .disableWriteActions

# 如果为 true，修改 Temporal UI Server 启动参数
# 在 docker-compose.yml 中添加环境变量
environment:
  - TEMPORAL_DISABLE_WRITE_ACTIONS=false
```

### 9.5 主题切换不生效

**原因**：可能是浏览器缓存了旧的 CSS。

**解决**：
- 强制刷新：`Ctrl + Shift + R`（Mac: `Cmd + Shift + R`）
- 清除 localStorage：浏览器控制台执行 `localStorage.clear()`
- 检查 `config.js` 中 `defaultTheme` 配置

### 9.6 部署后 config.js 修改未生效

**原因**：浏览器缓存了旧的 config.js。

**解决**：Nginx 配置中已设置 `no-cache`，如果仍未生效：
```bash
# 强制刷新
curl -H "Cache-Control: no-cache" http://localhost/config.js

# 或在 URL 后加版本号
# https://example.com/config.js?v=2
```

### 9.7 计划任务页面报错 "Cannot read properties of undefined (reading 'map')"

**原因**：Temporal API 返回的 `schedules` 字段为 undefined。

**解决**：已在 v1.0 修复，`fetchSchedules` 函数会防御性处理空响应。如仍出现，检查 Temporal Server 版本是否支持 Schedules API（需 ≥ 1.18）。

## 10. 回滚策略

### 10.1 快速回滚（保留备份）

部署脚本已自动备份旧版本，回滚只需切换目录：

```bash
# 1. 查看历史备份
ls -d /var/www/ui-redesign.bak.*

# 2. 选择要回滚的版本
ROLLBACK_DIR=/var/www/ui-redesign.bak.20260817150000

# 3. 执行回滚
sudo rm -rf /var/www/ui-redesign
sudo cp -r $ROLLBACK_DIR /var/www/ui-redesign
sudo nginx -s reload

# 4. 验证
curl -I http://localhost/
```

### 10.2 Git 版本回滚

```bash
# 1. 查看历史提交
git log --oneline -10

# 2. 回滚到指定版本
git checkout <commit-hash>
pnpm install --frozen-lockfile
pnpm build:prod

# 3. 部署
sudo cp -r dist/* /var/www/ui-redesign/
sudo nginx -s reload
```

### 10.3 蓝绿部署（零停机）

适合生产环境的零停机部署方案：

```bash
# 目录结构
/var/www/
├── ui-redesign-blue/    # 蓝环境（当前生产）
├── ui-redesign-green/   # 绿环境（待切换）
└── ui-redesign -> /var/www/ui-redesign-blue  # 软链接

# 部署步骤
# 1. 部署新版本到绿环境
sudo cp -r dist/* /var/www/ui-redesign-green/

# 2. 测试绿环境
curl -I http://localhost:8081/  # 通过临时端口测试

# 3. 切换软链接
sudo rm /var/www/ui-redesign
sudo ln -s /var/www/ui-redesign-green /var/www/ui-redesign
sudo nginx -s reload

# 4. 如有问题，立即切回蓝环境
sudo rm /var/www/ui-redesign
sudo ln -s /var/www/ui-redesign-blue /var/www/ui-redesign
sudo nginx -s reload
```

### 10.4 数据库回滚（如适用）

如果部署涉及数据库 schema 变更：

```bash
# 1. 部署前备份数据库
pg_dump -h localhost -U temporal temporal > /backup/temporal-$(date +%Y%m%d).sql

# 2. 回滚数据库
psql -h localhost -U temporal temporal < /backup/temporal-20260817.sql

# 3. 重启 Temporal Server
docker compose restart temporal-server
```
